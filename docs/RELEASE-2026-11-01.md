## Что проверено на рабочих адресах

В Chromium прошли 14 проверок страниц: главные страницы пяти сайтов на ширинах 1440 и 390 px, каталог и объект Luxury Realty, AVA 1601 и Atlantis 3402 на мобильной ширине. Это проверка опубликованной версии, а не только локальной сборки.

Для каждой страницы проверены HTTP 200, адрес после перенаправлений, заголовок, загрузка и декодирование каждой картинки, загрузка объявленных шрифтов, горизонтальное переполнение и ошибки JavaScript/консоли. Все проверки прошли. Из карточек проектов Luxury Realty проверены переходы на четыре соответствующих опубликованных сайта.

Сохраненные проектные проверки дополнительно покрывают фильтры, возврат в каталог, галереи, планировки, мобильное меню, фокус/Escape и состояния формы. Их подробный охват описан в README каждого проекта. Текущий общий прогон не заменяет эти проверки и не объявляет покрытие всех возможных устройств.

## Реальное сохранение заявок

На каждом из пяти опубликованных сайтов выполнен одинаковый тест настоящего API с явно синтетическими данными:

| Действие | Подтвержденный ответ |
| --- | --- |
| Создать корректную заявку | HTTP 201, подтвержденный номер |
| Повторить те же данные с тем же номером | HTTP 200, тот же номер |
| Повторить номер с измененными данными | HTTP 409, прежняя запись не перезаписана |
| Отправить без согласия | HTTP 422 |
| Отправить с постороннего origin | HTTP 403 |
| Вызвать endpoint через GET | HTTP 405 |

Обработчик сохраняет заявки в приватном Vercel Blob. Повторная отправка проверяет уже сохраненную запись, поэтому успех подтвержден настоящим хранилищем. В тестовых записях явно указано, что действий не требуется. Письма и сообщения внешним получателям не отправлялись.

В отдельной выборке runtime logs пяти production-проектов за 15 минут не найдено групп уровня error/fatal. Это результат ограниченного окна наблюдения, а не гарантия отсутствия будущих ошибок.

## Исправленная проверка изображений

Исходный общий тест вызывал decode() одновременно для всех изображений длинной страницы. На ORLA это дало 24 отказа для 83 уже загруженных элементов. Последовательный decode() тех же неизмененных элементов прошел для всех 83; отсутствующих изображений не было.

Проверочный скрипт теперь ограничивает одновременное декодирование и число страниц. Требования к каждой картинке сохранены: успешная загрузка, ненулевой размер и успешный decode(). Ошибки не игнорируются. Изображения сайтов ради прохождения теста не заменялись. Финальный общий прогон прошел полностью, включая ORLA и Six Senses.

## Что еще зависит от исходных материалов

- Заявки сохраняются в приватное хранилище владельца. Отправка в почту или CRM пока не подключена.
- Каталоги используют переданные данные и фотографии. Подключенной базы актуальных цен и доступности нет; это не система бронирования.
- Оригинальные фильмы и ряд PDF-презентаций/платежных планов не были переданы. Кнопки открывают соответствующий запрос или честное состояние отсутствия материала.
- В Atlantis предоставлена подробная резиденция 3402; в AVA сохранены отдельные страницы 801 и 1601; в Six Senses сохранены два исходных типа планировок. Дополнительный инвентарь не придумывался.
- Исходные противоречия характеристик ORLA 401 не представлены как подтвержденные коммерческие данные. Сохранена исходная планировка и запрос актуальных условий.
- Контакты, реквизиты, коммерческие характеристики и юридические тексты требуют подтвержденных данных владельца перед запуском рекламы. Эта приемка не проверяет достоверность таких данных.

## Повторная проверка

Из корня LuxuryRealty:

```sh
node scripts/production-qa.mjs
```

Скрипт проверяет все пять опубликованных сайтов. Заявки в браузерной проверке заблокированы; результат и скриншоты попадают в игнорируемый каталог `artifacts/production-browser`. Общий Playwright берется из серверного toolkit; путь можно задать через `PLAYWRIGHT_PATH`, результат через `SMOKE_OUTPUT`.

Отдельная реальная проверка API создает одну синтетическую запись в выбранном проекте:

```sh
python3 scripts/production-api-qa.py https://luxury-realty-imon.vercel.app luxury-realty
```

На рабочем сервере длительные проверки выполняются через очередь `imon-job`. Подтвержденные задания этого выпуска: `20261101T112600-5d2bec947f` (API пяти проектов), `20261101T112804-189f9153e7` (14 браузерных проверок), `20261101T113242-e1bee8bed0` (сборка и TypeScript после правки метаданных ORLA).

Машиночитаемый результат: [production-2026-11-01.json](verification/production-2026-11-01.json). В нем нет данных посетителей, токенов или содержимого приватных заявок.
